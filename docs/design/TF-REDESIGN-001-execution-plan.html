PROJECT EXECUTION PLAN · TF-REDESIGN-001

TradeForge Frontend Visual Redesign & Landing Page

Date 2026-09-13 Design Owner Usha Implementation Owner Arjun PM Krishna Approver Atharva
Planning — Not Started
Problem: The TradeForge web application has no visual identity beyond raw function. Cards have equal weight with no hierarchy. The sidebar is text-only with no brand treatment. Auth pages are plain white with no brand presence. There is no public landing page — unauthenticated visitors land directly on /login with no product framing. The app does not read as a professional trading tool.
Scope
In Scope
  • New public landing page at /
  • AppShell sidebar — icons, brand logo, visual grouping
  • Dashboard — stat tile hierarchy, card grid layout
  • Auth pages — Login, Register, ForgotPassword, ResetPassword, VerifyEmail, RegisterSuccess
  • Analytics page — card grid spacing and hierarchy
  • TradeList & TradeDetail — table polish and spacing
  • Design token extensions in tokens.css (Usha-owned)
  • Light and dark theme correctness across all pages
Out of Scope
  • New features or data-model changes
  • Backend API changes
  • Mobile/responsive overhaul
  • Component library or Storybook setup
  • Animation system or motion design
  • Risk page (currently a placeholder — deferred)
  • Settings page visual redesign
  • New npm packages without Arjun's explicit sign-off
Product Goals
G-1
First impression exists. A visitor who lands on the TradeForge URL sees a product, not a login form. The landing page communicates what TradeForge is and who it's for within 5 seconds.
G-2
Visual hierarchy is legible. The most important numbers on any page (P&L, win rate, equity) are visually dominant. Supporting context is subordinate. A user can scan the dashboard in under 3 seconds and find what matters.
G-3
Brand identity is consistent. The TradeForge name, color, and typographic voice appear consistently across the sidebar, auth pages, and landing page. It looks like one product.
G-4
Cards and layout are intentional. Elements are positioned on a consistent grid. Cards are sized to their content. Nothing is misaligned, floats in dead space, or stretches incorrectly.

Constraints
⚠ All existing frontend tests (currently 359) must continue to pass. Implementation may not modify test expectations without a corresponding defect being logged and Sahadeva informed.
⚠ Design tokens in tokens.css are the single source of truth for color and theming. No hardcoded color values in component files. Usha may add tokens; removal requires Arjun sign-off.
⚠ No new npm dependencies without Arjun's explicit sign-off. Icon sets must be either inline SVG or a dependency Arjun approves.
⚠ No backend API changes. No changes to URL routing except adding the new public / route. All authenticated routes and their behavior remain unchanged.
⚠ Implementation must not begin until Atharva has approved Usha's Phase 1 design spec. Premature implementation that diverges from the spec will be reverted.
⚠ TypeScript strict mode must remain clean throughout. tsc --noEmit must pass before Arjun's handoff to Sahadeva.
Acceptance Criteria
Landing page is visible to unauthenticated users at / and communicates TradeForge's purpose without requiring login.
Authenticated users navigating to / are still redirected to /dashboard with no regression in auth behavior.
Sidebar includes icons for all navigation items and a legible brand logo treatment for "TradeForge".
Dashboard key metrics (All-time P&L, Win Rate, Expectancy) are visually dominant — larger text weight or dedicated stat tile treatment — over secondary information.
All 6 auth pages share a consistent brand layout with the TradeForge visual identity (not plain white centered card with no context).
All pages render correctly in both light and dark themes. No text is unreadable, no surface is transparent, no element disappears in either mode.
All 359 existing frontend tests pass. No new TypeScript errors introduced.
Atharva approves the final visual output after Phase 3 QA completes.
