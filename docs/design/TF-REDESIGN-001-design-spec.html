01 · Design Rationale

Precision tool, not a consumer app

TradeForge serves Indian retail traders who review trades in focused sessions — evenings, weekends, between market hours. They scan P&L figures the way developers scan logs: quickly, looking for anomalies. The interface must surface numbers first, context second, decoration never. Every visual decision follows from this: dark-first, data-dense, typographically precise.

The primary color upgrades from #2563EB (Tailwind blue-600, generic SaaS) to #4F46E5 (indigo-600). Indigo reads as analytical and deliberate — closer to tools than products. It still clears WCAG AA against white (4.7:1). The font upgrades from system-ui to Plus Jakarta Sans for all UI text, and JetBrains Mono for all numeric data — the same typeface a professional trader uses in their IDE.

⚠ Primary color change (#2563EB → #4F46E5) requires Atharva sign-off before Arjun implements. All other changes are within Usha's authority.

19 · Theme Toggle — Item 10a

Theme toggle: landing page + authenticated app

A single icon button appears on both the public landing page and the authenticated sidebar. One localStorage key (tf-theme) drives both surfaces — the preference persists across navigation between public and authenticated views.

Overview & rationale

Traders work at screens for hours. Theme is a meaningful comfort choice, not a novelty — it must be discoverable before login (landing page) and persistent once set. The same preference value must not reset on navigation. No separate "system" UI control is exposed after the user makes their first explicit choice; the OS preference is the default state only.

Shared state contract: On app init (before first render), read localStorage.getItem('tf-theme'). If "light" or "dark", apply data-theme to <html> immediately. If absent, fall back to prefers-color-scheme — do not write to localStorage at this point. Write only when the user explicitly clicks the toggle.

Icon swap transition

When the toggle fires, the icon swaps (sun ↔ moon). Use a short opacity fade to avoid a jarring instant swap:

/* CSS on the icon element */
transition: opacity 150ms ease-in-out, color 150ms ease-in-out;

/* On swap: set opacity:0, swap SVG, set opacity:1 */
/* Respect prefers-reduced-motion: skip transition, swap immediately */
@media (prefers-reduced-motion: reduce) {
  .theme-toggle-icon { transition: none; }
}

Implementation notes for Arjun

Extract toggle logic into a useTheme() hook: manages reading/writing tf-theme, applying data-theme to <html>, and returning { theme, setTheme }. Both the landing page and sidebar components consume the same hook — this guarantees the shared-key contract is enforced in one place.
Apply data-theme to <html> in a script that runs before the React root mounts (index.html inline script or main.tsx top-of-file). This eliminates the flash of incorrect theme on reload. Do not do this inside a useEffect — that fires after paint.
The landing page toggle and the app sidebar toggle are separate component instances but share state through localStorage and the data-theme attribute on <html>. No React context or prop-drilling is needed — each toggle instance reads from and writes to the same key and the same DOM attribute.
